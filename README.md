# AI 简历优化助手

基于大语言模型（LLM）的简历诊断与优化 Web 应用：上传简历后自动解析文本，提供 **诊断评分、问题分析、优化建议、简历改写、模拟面试题、多轮助手对话** 六大 AI 能力，并通过轻量级 RAG 知识库检索简历写作知识，为 AI 结果标注参考来源，降低模型幻觉风险。

---

## 1. 项目背景与定位

求职过程中，简历是获取面试机会的第一道门槛。多数求职者（尤其是应届生）面临以下痛点：

- 不知道简历在 HR / ATS（简历筛选系统）眼中的真实水平；
- 缺乏针对目标岗位的关键词匹配与缺口分析；
- 项目经历描述平淡，不会使用 STAR 法则等结构化表达；
- 网上资料零散，缺乏针对**自己这份简历**的可执行建议。

本项目定位为**面向个人求职者的轻量级简历优化工具**（同时可作为课程设计 / 毕业设计演示项目），通过调用大模型 API 实现简历的自动化诊断与改写，并以 RAG 知识库约束输出、以来源标注提升可解释性。

核心设计原则：

- **Prompt 即配置**：六大场景全部使用数据库化 Prompt 模板，管理员可在后台新增/编辑模板，无需改代码；
- **模型可切换**：支持配置多个 LLM 服务商与模型（如 DashScope qwen-plus），按场景选择；
- **可解释性**：AI 结果附带知识库参考来源（标题 + 相似度），历史记录完整留痕。

## 2. 功能列表

### 用户端

| 模块 | 功能 |
| --- | --- |
| 账号 | 注册 / 登录（JWT 鉴权，7 天有效期）、个人资料与头像修改 |
| 简历管理 | 上传解析（PDF / Word docx / TXT / HTML）、粘贴与在线编辑、多简历切换、目标岗位与 JD 维护、导出 Word |
| 诊断评分 | 0–100 结构化评分 + 等级（优秀/良好/合格/待改进）+ 诊断分析（Markdown 渲染） |
| 问题分析 | 流式（SSE）输出核心问题与岗位适配分析 |
| 优化建议 | 亮点提炼、量化成果、删减冗余、关键词匹配、缺口分析 |
| 简历改写 | 三种模板（轻度润色 / STAR 法则 / 专业化），生成候选版本，确认后采纳覆盖 |
| 模拟面试题 | 基于简历与目标岗位生成分类面试题（可折叠展开） |
| 助手对话 | 多轮上下文对话（服务端校验并裁剪历史），知识库检索辅助回答 |
| 知识库来源标注 | 评分 / 分析 / 建议 / 改写 / 面试题 / 对话结果均显示引用的知识库条目与相关度 |
| AI 历史记录 | 按类型筛选查看历次 AI 调用的输入输出、耗时、模型与引用来源 |
| 体验优化 | 上传进度条、表单校验、错误提示、移动端适配（窄屏侧栏图标化、布局纵向堆叠） |

### 管理端

| 模块 | 功能 |
| --- | --- |
| 系统首页 | 用户 / 简历 / 调用次数统计仪表盘（ECharts 图表） |
| 用户管理 | 用户列表、关键词搜索、启用/禁用、重置密码 |
| AI 历史记录 | 全量调用记录查询（按用户 / 类型 / 模型筛选） |
| 模型配置 | 多服务商配置（base_url + API Key + 模型名），启用/禁用，指定默认 |
| Prompt 模板 | 六大场景模板 CRUD、搜索筛选、批量删除、状态开关 |

### 安全特性

- 上传文件魔数校验（防伪造扩展名）、Word 宏（VBA）检测并拒绝、文本类文件二进制伪装（NUL 字节）检测；
- 上传大小限制（10MB）、扩展名白名单；
- 密码 bcrypt 哈希存储，JWT 鉴权，接口按用户隔离数据。

## 3. 技术栈

| 层 | 技术 |
| --- | --- |
| 后端 | Python 3.10+、FastAPI、SQLAlchemy 2.0、PyMySQL、PyJWT、python-multipart |
| AI 接入 | OpenAI SDK 兼容模式（阿里云百炼 DashScope：`qwen-plus` 对话、`text-embedding-v3` 向量） |
| RAG | 轻量自研向量检索：向量以 JSON 存于 `knowledge_chunks.embedding`，纯 Python 余弦相似度 Top-3（接口与 FAISS / Chroma 同构，可平滑替换） |
| 文档解析 | pypdf（PDF）、python-docx（Word）、BeautifulSoup（HTML） |
| 数据库 | MySQL 8.0（utf8mb4） |
| 前端 | Vue 3（CDN 全局构建）、Vue Router、Element Plus、Axios、Marked、ECharts |
| 部署形态 | 前后端分离：Uvicorn 承载 API，任意静态服务器承载前端 |

## 6. 安装步骤

1. **获取代码**：将项目目录复制到本地任意位置（下文以项目根目录 `2/` 为例）。

2. **安装 Python 依赖**：

   ```bash
   cd backend
   pip install -r requirements.txt
   ```

3. **准备数据库**：确保本机 MySQL 已启动，并准备好 root（或其他）账号密码。数据库 `resume_optimizer` 由初始化脚本自动创建，无需手工建库。

4. **配置环境变量**：编辑 `backend/.env`（首次可自建，模板如下）：

   ```ini
   DB_HOST=127.0.0.1
   DB_PORT=3306
   DB_USER=root
   DB_PASSWORD=你的数据库密码
   DB_NAME=resume_optimizer
   JWT_SECRET=请替换为随机长字符串
   ```

5. **初始化数据库**（建表、结构迁移、写入种子数据：默认账号、18 个 Prompt 模板、12 条知识库片段）：

   ```bash
   python init_db.py
   ```

   脚本可重复执行（幂等），升级后再次运行即可自动补列/更新模板。

6. **配置模型**：首次启动后，用管理员账号登录管理端「模型配置」页，新增一条配置：
   - 服务商：`阿里云百炼 DashScope`（名称可自定义）
   - Base URL：`https://dashscope.aliyuncs.com/compatible-mode/v1`
   - API Key：你的 DashScope 密钥
   - 模型名称：`qwen-plus`（对话）/ Embedding 模型固定使用 `text-embedding-v3`

## 7. 启动方式

### 方式一：Windows 脚本（推荐）

双击根目录：

- `start_backend.bat` —— 启动后端 API（http://127.0.0.1:8000）
- `start_frontend.bat` —— 启动前端静态服务（http://127.0.0.1:5173）

### 方式二：命令行

```bash
# 终端 1：后端
cd backend
python run.py

# 终端 2：前端（任意静态服务器均可，示例为 Python）
cd frontend
python -m http.server 5173
```

启动完成后访问 **http://127.0.0.1:5173**。

> 如需将前端部署到其他端口/域名，请修改 `frontend/index.html` 中的 `window.API_BASE`，并确认后端 CORS 允许该来源（见 `backend/app/main.py`）。

### 内置演示账号

| 角色 | 用户名 | 密码 |

| 管理员 | admin | 123456 |

### 典型使用流程

1. **登录**：使用演示账号或自行注册（注册即普通用户）。
2. **进入工作台**：填写「简历标题」与「目标岗位」，上传简历文件（PDF/DOCX/TXT/HTML，≤10MB）或直接在左侧文本框粘贴简历内容，点击「保存当前文本」。也可在「已有简历」下拉切换历史简历。
3. **诊断评分**：右上选择模型配置与 Prompt 模板（默认即可），点击「生成评分」，得到分数、等级与诊断分析，下方展示知识库参考来源。
4. **问题分析 / 优化建议**：点击对应 Tab 的生成按钮，AI 流式输出结果，完成后显示引用来源。
5. **简历改写**：选择改写模板（轻度润色 / STAR / 专业化），生成候选版本后点击「采纳为当前简历」才会覆盖，原始解析文本始终保留可查。
6. **模拟面试题**：一键生成分类面试题，折叠面板逐类展开。
7. **助手对话**：在「助手对话」Tab 中多轮提问（如"STAR 法则怎么用在项目经历上？"），AI 结合当前简历与知识库回答，每轮回答下方标注引用的知识库条目；可随时「清空对话」重新开始。
8. **导出**：编辑满意后点击「下载当前简历」导出 Word。
9. **历史记录**：左侧菜单「AI 历史记录」可回看每次调用详情（含引用来源与耗时）。

### 管理端

管理员登录后自动进入管理端：系统首页看统计，「用户管理」「AI历史记录」「模型配置」「Prompt模板」分别维护对应数据。Prompt 模板支持六大场景（score / analysis / suggestion / rewrite / interview / chat），占位符 `{resume_text}`、`{target_position}`、`{job_desc}` 会在调用时自动替换；停用某场景全部模板时该场景回退使用种子默认模板。
